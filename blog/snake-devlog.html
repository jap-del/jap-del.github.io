터닝 스네이크 개발기: 격자 게임 루프와 입력 버퍼

개발기2026년 11월 10일 · 게임 허브

뱀 게임은 프로그래밍 입문 과제로 자주 나오지만, 막상 "손맛 좋게" 만들려면 신경 쓸 것이 꽤 있습니다. 터닝 스네이크를 만들며 고민한 부분을 정리했습니다.

격자와 틱: 점프잇과 다른 게임 루프

점프잇은 매 프레임 위치를 조금씩 움직이는 연속적인 게임이지만, 뱀 게임은 20×20 격자 위에서 한 칸씩 움직입니다. 그래서 화면 그리기와 게임 진행을 분리했습니다.

function loop(now){
  var dt = now - lastT; lastT = now;
  acc += dt;                 // 흐른 시간을 모아 두었다가
  while(acc >= tick){        // 한 틱만큼 쌓일 때마다
    acc -= tick; step();     // 한 칸 이동
  }
  draw();                    // 그리기는 매 프레임
  requestAnimationFrame(loop);
}

이렇게 시간을 모아 두는 방식(누산기)을 쓰면 모니터 주사율과 상관없이 같은 속도로 움직입니다. tick은 처음 140ms에서 시작해 빨간 먹이를 먹을 때마다 2ms씩 줄고(최소 65ms), 파란 먹이를 먹으면 10ms 늘어납니다.

방향은 벡터로, 역방향은 막기

뱀의 진행 방향은 {x, y} 벡터로 저장합니다. 오른쪽은 (1, 0), 아래는 (0, 1), 위는 (0, -1)입니다. 화면 좌표는 아래로 갈수록 y가 커지기 때문입니다. 키보드 입력도 같은 형태로 바꿔 두면 처리가 단순해집니다.

var KEYS = { ArrowUp:[0,-1], ArrowDown:[0,1], ArrowLeft:[-1,0], ArrowRight:[1,0] };

뱀 게임에서 꼭 막아야 하는 입력이 정반대 방향입니다. 오른쪽으로 가는 뱀이 바로 왼쪽으로 돌면 머리가 목에 부딪혀 즉시 게임이 끝나 버립니다. 벡터로 저장해 두면 "두 벡터의 합이 0"인지만 보면 되므로 한 줄로 검사할 수 있습니다.

if(dx === -p.x && dy === -p.y) return; // 정반대면 무시

뱀 눈의 위치도 진행 방향에 수직인 벡터 (-y, x)를 이용해 그립니다. 네 방향마다 if문을 쓰지 않아도 된다는 것이 벡터를 쓰는 장점입니다.

참고로 처음 버전은 뱀 기준으로 왼쪽·오른쪽만 도는 방식이었습니다. 이때는 회전을 (x, y) → (y, -x), (x, y) → (-y, x) 식으로 계산했는데, 플레이해 보니 화면 기준 조작이 훨씬 직관적이어서 지금 방식으로 바꿨습니다. 그 이야기는 상대 방향 조작 글에 정리했습니다.

모바일 입력: 스와이프와 탭

휴대폰에서는 손가락이 처음 닿은 곳에서 24px 이상 움직이면 더 크게 움직인 축(가로 또는 세로)으로 방향을 정합니다. 손가락을 떼지 않고 다시 움직이면 그 지점부터 새로 계산해서 연속 스와이프도 됩니다. 스와이프 없이 톡 탭하면, 뱀 머리를 기준으로 탭한 쪽으로 꺾습니다. 뱀이 가로로 가고 있다면 머리보다 위를 탭했는지 아래를 탭했는지만 보면 됩니다.

입력 버퍼: 빠른 손을 놓치지 않기

뱀 게임에서 흔한 버그는 "키를 두 번 빨리 눌렀는데 한 번만 먹히는" 문제입니다. 한 틱이 지나기 전에 방향을 두 번 바꾸면, 마지막 입력으로 덮어써지기 때문입니다. 더 나쁜 경우도 있습니다. 오른쪽으로 가는 중에 한 틱 안에 ↑, ←를 누르면 각각은 정상 입력인데, 합쳐 보면 오른쪽에서 바로 왼쪽으로 꺾인 셈이 되어 자기 몸에 부딪히는 억울한 상황이 생깁니다.

터닝 스네이크는 입력을 큐(대기열)에 쌓아 두고 한 틱에 하나씩 꺼내 씁니다. 역방향 검사도 현재 방향이 아니라 큐의 마지막 방향과 비교합니다.

function planned(){ return queue.length ? queue[queue.length - 1] : dir; }
function go(dx, dy){
  var p = planned();
  if((dx === p.x && dy === p.y) || (dx === -p.x && dy === -p.y)) return;
  if(queue.length < 3) queue.push({ x: dx, y: dy });
}
function step(){
  if(queue.length) dir = queue.shift();
  // ... 한 칸 이동
}

덕분에 ↑, ←를 빠르게 이어 누르면 두 칸에 걸쳐 깔끔하게 U턴합니다. 큐 길이를 3으로 제한한 것은, 너무 많은 입력이 쌓여 한참 뒤에 엉뚱하게 꺾이는 것을 막기 위해서입니다. 자료구조 수업에서 배우는 큐가 게임 조작감에 바로 쓰이는 좋은 예입니다.

충돌 판정에서 꼬리 처리

몸과의 충돌을 검사할 때 놓치기 쉬운 부분이 꼬리입니다. 먹이를 먹지 않는 틱에는 머리가 한 칸 나아가는 동시에 꼬리가 한 칸 빠지므로, 머리가 방금 꼬리가 있던 칸으로 들어가는 것은 안전합니다. 그래서 먹이를 먹지 않을 때는 마지막 칸을 빼고 충돌을 검사합니다. 이 처리를 빼먹으면 꼬리를 바짝 따라가는 고급 플레이가 불가능해집니다.

먹이는 빈칸에서만

먹이를 무작위 위치에 놓았다가 몸과 겹치면 다시 뽑는 방식은, 몸이 길어질수록 여러 번 다시 뽑아야 해서 비효율적입니다. 터닝 스네이크는 매번 빈칸 목록을 만든 뒤 그중 하나를 고릅니다. 판이 400칸뿐이라 목록을 만드는 비용도 작고, 몸이 판을 거의 채워도 항상 한 번에 정확히 고를 수 있습니다.

먹이 종류는 빨강 70%, 파랑 15%, 금색 15% 확률로 정하고, 금색 먹이는 생긴 시각을 기억해 두었다가 6초가 지나면 빨간 먹이로 바꿉니다.

정리

  • 격자 게임은 누산기로 틱과 그리기를 분리한다.
  • 방향은 벡터로, 정반대 입력은 큐의 마지막 방향과 비교해 막는다.
  • 입력은 큐에 쌓아 한 틱에 하나씩.
  • 충돌 검사에서 꼬리 칸을 빼 주는 것을 잊지 말 것.

완성된 결과는 터닝 스네이크에서 확인할 수 있습니다.
