점프잇 개발기 ①: 캔버스와 게임 루프 만들기

개발기2026년 10월 19일 · 잽델 게임즈

점프잇은 별도의 게임 엔진 없이 HTML5 캔버스와 순수 자바스크립트로 만들었습니다. 첫 번째 개발기에서는 모든 게임의 심장이라고 할 수 있는 게임 루프를 어떻게 만들었는지 정리합니다.

게임 루프란?

게임은 1초에 수십 번씩 같은 일을 반복합니다.

  1. 업데이트: 캐릭터와 장애물의 위치, 점수, 충돌 여부를 계산합니다.
  2. 그리기: 계산된 상태대로 화면을 다시 그립니다.

이 두 단계를 계속 반복하는 구조를 게임 루프라고 합니다.

setInterval 대신 requestAnimationFrame

처음에는 setInterval로 일정 시간마다 함수를 부르는 방법을 떠올리기 쉽습니다. 하지만 브라우저 게임에서는 requestAnimationFrame을 쓰는 것이 좋습니다.

  • 모니터가 화면을 새로 그리는 타이밍에 맞춰 호출되어 움직임이 부드럽습니다.
  • 탭이 백그라운드로 가면 자동으로 멈추거나 느려져 배터리를 아낍니다.
function loop(now){
  if(state !== 'playing') return;
  var dt = Math.min((now - lastT) / 1000, 0.033);
  lastT = now;
  update(dt);
  draw();
  requestAnimationFrame(loop);
}

델타 타임: 모니터가 달라도 같은 속도로

모니터 주사율은 기기마다 다릅니다. 60Hz 화면에서는 1초에 60번, 144Hz 화면에서는 144번 루프가 돕니다. 매 프레임 "5픽셀씩 이동"처럼 만들면 144Hz 화면에서 게임이 두 배 이상 빨라지는 문제가 생깁니다.

그래서 이전 프레임과의 시간 차이인 델타 타임(dt)을 구해, 모든 움직임을 "초당 얼마"로 계산합니다. 위치 += 속도 × dt로 계산하면 어떤 화면에서도 같은 속도로 움직입니다.

위 코드에서 dt를 최대 0.033초(약 30fps 한 프레임)로 제한한 것도 중요합니다. 컴퓨터가 잠깐 멈췄다가 돌아오면 dt가 크게 튀는데, 그대로 계산하면 캐릭터가 장애물을 순간이동하듯 통과해 버릴 수 있기 때문입니다.

선명한 화면: devicePixelRatio 대응

요즘 스마트폰과 노트북은 CSS 픽셀 하나에 실제 화면 픽셀이 2~3개씩 들어가는 고해상도 화면을 씁니다. 캔버스를 CSS 크기 그대로 만들면 이런 화면에서 흐릿하게 보입니다.

var DPR = Math.min(window.devicePixelRatio || 1, 2);
canvas.width  = Math.round(W * DPR);
canvas.height = Math.round(H * DPR);
ctx.setTransform(DPR, 0, 0, DPR, 0, 0);

캔버스의 실제 픽셀 수는 배율만큼 키우고, 그리기 좌표는 setTransform으로 원래 크기 기준을 유지합니다. 배율을 최대 2로 제한한 것은 3배 화면에서 그려야 할 픽셀이 너무 많아져 성능이 떨어지는 것을 막기 위해서입니다.

화면 크기에 비례하는 게임 세계

점프잇의 게임 화면은 16:9 비율을 유지하면서 화면 폭에 맞춰 늘어나고 줄어듭니다. 그래서 캐릭터 크기, 점프 높이, 이동 속도를 모두 화면 크기에 대한 비율로 정했습니다. 예를 들어 땅의 높이는 화면 높이의 82% 지점, 달리는 속도는 화면 폭의 42%를 1초에 이동하는 값에서 시작합니다. 덕분에 휴대폰과 큰 모니터에서 같은 감각으로 플레이할 수 있습니다.
